## 一句话主张

在冻结 LeWM 上提出一个**轻量边界分类器**：无监督物理特征（潜变量增量流的能量占比、方向偏转）形式固定，**结合方式可学习**（小型融合头）；检测到物理相变就提前终止当前执行段、从真实观测重锚定重规划。PushT 长距离下，边界触发停止比平坦规划成功率更高——证明这一点就收工。

# 执行细化：分类器特征设计与提取（11/2 启动，动作 3 前置）

## 状态快照

- 平坦规划基线：4/9 组完成（d25: 88.0/92.0，d50: 50.0，d75: 16.0 vs 发表 94.0/52.7/18.0），崩溃模式已复现，作业后台继续跑余下 5 组
- 数据事实（已实测）：`state` = [agent_x, agent_y, block_x, block_y, block_angle, v_x, v_y]；18,685 条轨迹，ep_len 49–246（中位 123）；encoder 接口 = `model.encode({'pixels': (B,T,224,224,3)})['emb']` → 每帧 192 维 CLS 潜变量

## 特征设计（无监督物理特征，3 个，全部在潜增量流上）

对每条轨迹：z_t = Enc(o_t) ∈ R^192，增量 Δz_t = z_{t+1} − z_t。

**分解（闭式线性 SFA，fit 在训练集上，一次性）**：
1. 白化：PCA(Σ_z) → W_pca（192 维全保留）
2. 白化空间增量 u_t = W_pcaᵀΔz_t，PCA(Σ_u) 得旋转 V，按特征值升序排列（最慢在前）
3. 总变换 W = W_pca·V：慢子空间 P_slow = W[:, :16]，快子空间 P_fast = W[:, −16:]
4. fit 落盘 `runs/feature_fit.json`（谱值、k、子空间能量占比，作退化检查）

**逐时刻特征**：
- f1 能量切换：fast 子空间能量占比 ‖P_fastᵀΔz_t‖²/‖Δz_t‖²，w=5 滑窗平滑后减去该轨迹中位数基线
- f2 方向偏转：慢子空间内连续增量余弦 cos(P_slowᵀΔz_t, P_slowᵀΔz_{t−1})
- f3 增量能量：log(1+‖Δz_t‖²)

**运动学参考事件（机械提取，零人工标注）**：agent-块距离 d(t) 越阈为接触（r_c≈30px）、回升为脱离；块位移 >0.5px 持续 2 步为块运动起始。现在作特征验证的真值参考，之后直接复用为融合头训练标签。

## 三个脚本（全部落 aiim2026/src/，产物落 runs/）

1. `extract_latents.py`：抽 400 条轨迹（seed=0；300 训练 / 100 留出），像素变换与 eval_wm.py 完全一致（ImageNet 归一化 + 224），MPS 批量编码 → `runs/latents_{train,hold}.npz` + 对齐的 state 行 → `runs/states_{train,hold}.npz`（约 49k 帧，ViT-tiny，预计 2–4 分钟）
2. `fit_features.py`：训练集上做 SFA 分解 → 按上表提取三个特征 → `runs/features_{train,hold}.npz` + `runs/feature_fit.json`
3. `verify_features.py`：验收门（见下），出 `runs/feature_overlay.png`（5 条留出轨迹：f1/f2/f3 曲线 + 接触/脱离/块运动竖线标记）+ `runs/feature_sanity.json`

## 运行正确性的验收门（三道）

1. **Sanity**：形状对齐（每轨迹 T−1 个特征点）、无 NaN、f1∈[0,1]、f2∈[−1,1]、快子空间承载 ≥15% 增量能量（防退化）
2. **定性目检**：5 条留出轨迹的特征曲线在运动学事件处有可见响应（能量占比抬升 / 方向余弦骤降），图逐张目检
3. **快速 AUC**：留出集上单特征对接触事件（±3 步容差）的 AUC，三个特征各自 > 0.55（非随机底线；融合头的任务是把它们合起来，不要求单特征强）

## 与下一步的衔接

特征验收通过后 → 融合头（小型 MLP）用同一批运动学事件标签训练 → 留出 F1 + 乱序阈值对照 → 两臂对比。特征和标签的提取管线完全复用，不重写。

# 真值修正（11/2 晚，用户要求复查事件真值后发现）

**发现的 bug**：原 contact/detach 用"agent-块距离越阈 r_c=30px"判定，是错的。三个证据链：
1. 数据反常：块在 dist 50-90px 时高速移动的帧有 1,989 个（比 dist<50 的 1,105 还多）——如果 r_c=30 是接触，这就是"块隔空被推"
2. 读 env 源码（stable_worldmodel/envs/pusht/env.py）查明根因：块不是小 T，是 8 种多方块形状（'o','L','T','Z','square','I','small_tee','+'），scale∈[20,60]，T 的最远角距中心 2.24×scale≈45-134px——**推边缘时中心距天然在 50-90px**；且 space.damping=0，块被推后无阻力滑行
3. state schema 本身没错（pair01=agent，与速度维相关性 0.989 确认），错的是接触的几何假设

**修正**：事件改为与形状无关、直接可观测的两种（fit_features.py kinematic_events 重写）：
- push_onset：块位移 >0.5px/步 持续 2 步（原 block_move 不变，本来就对）
- settle：运动结束后位移 <0.1px/步 持续 3 步的首帧
- 噪声地板实测：agent>120px 且块已静默时 p99=0.89px，>0.5px 占 1.4%，0.5 阈值 + 2 步持续条件足够干净
- 检查工具：event_check.py（表 + 信号图 runs/event_check.png + 原始帧条 runs/event_frames.png，5 条 hold 轨迹逐事件目检）

**修正后数字（hold 集，±3 步容差，方向训练集定）**：
- 单特征对事件并集：f1 **0.641**（原 0.591，+0.05 成为最强特征——物理故事对上了：块起停=结构切换=f1 的本职）、f2 0.580、f3 0.574，全过 0.55 线
- 逐事件：f1 对 settle 0.637 / 对 push_onset 0.602
- 三特征逻辑回归融合：hold AUC **0.683**（原口径 0.656）
- 事件计数：train 1061 push + 680 settle；hold 349 push + 228 settle（300/100 条轨迹）

**教训（写论文时别踩）**：这个数据集的 PushT 不是经典小 T PushT——方法节描述环境时必须写清楚块形状族，且"接触"类标签不可用中心距离定义。
